# 题面（`subject`）进 front-matter：身份是结构，不是从正文猜出来的

## 问题

Phase 5 的两件事都建立在一个判断上：**这两条说的是不是同一件事**。
归并（S18）要靠它决定"并入还是新建"，冲突（S19）要靠它决定
"这条新事件是不是在推翻某条已有的 state"。

模型抽出来的**候选断言**可以带一个题面：抽取器的输出契约里加一个字段就够了。
但**已经落盘的资产**（`assets/state/*.md`）没有任何字段能表达它说的是哪件事：

- `id` 是 ULID，除"什么时候写的"之外不携带任何语义（ADR-0007）；
- `sources` 指向**证据**，而两条互相矛盾的状态恰恰来自两处**不同**的证据——
  拿证据当身份，冲突永远检测不到；
- `body` 是给人读的自由文本。手写的资产首行是 `# 标题`，而 `promote`
  出来的资产正文是从候选原样搬过来的事件原文——**它连标题都没有**。

于是在 P5 开工的第一天就撞上一个绕不过去的问题：
**身份住在哪里？**

## 考虑过的选项

1. **从正文猜。** 用首行标题、或正文的前 N 个字符做身份键。
   零 schema 改动，最省事。代价是身份随排版漂移：同一件事换一句标题就是两个实体，
   而**两个实体意味着不会有冲突被报出来**——失效的方式是静默的。
   词法相似度做身份还有第二个问题：它需要调阈值，而阈值会把
   "是不是同一件事"变成一个可以拧松的数字。

2. **把题面塞进正文的约定行。** 比如正文第一行固定写成 `题面：数据库的存储层`。
   对人可见，也不需要动 schema。代价是**第二真相**：题面成了正文的一部分，
   而资产审核（`judgeAsset`）看不到它，一致性闸门看不到它，
   任何人都能在编辑器里顺手改掉它而不触发任何检查。
   它还会让"正文可以原样复制"这条性质失效——`promote` 现在原样搬候选正文，
   一旦正文里要混进结构化字段，搬的时候就得解析它。

3. **front-matter 加一个字段 `subject`，并让 `state` 必填。**
   身份落在结构层，和 `id` / `sources` / `last_confirmed` 同级：
   审核能查、一致性闸门能比对模板、`REQUIRED_FIELD_MISSING` 能报红。

4. **把身份放进 `index/`（派生层），由 `promote` 时写入一份 资产 ID → 题面 的映射。**
   看起来最"轻"：index 层反正是可重建的。但它**建不起来**——映射的另一半
   （题面）只存在于 headers 里，而不在资产里。一份"删掉就重建不出来"的
   index 文件，正是 ADR-0015 要拦的东西（派生层一旦存了不可重算的东西，
   它就变成了第二份真相）。

## 选定

**选 3。** `subject` 是 front-matter 的一个字段：

- **`state` 必填**（写进 `schema/taxonomy.yaml` 的 `requires_fields`，由
  `REQUIRED_FIELD_MISSING` 强制）。判据很直接：**题面缺失 = 这条状态不参与冲突判定**，
  而"我确认过的状态不会被任何后续事件挑战"是这个产品最不能出的静默故障。
  把它做成必填，"缺失"就是一个能被报出来、能被修的红，而不是一片安静。
- **`decision` / `event` / `rule` 可选。** 归并（S18）对所有类型都有意义
  （两条 rule 讲的是同一件事），但**冲突**只发生在 `state` 上
  （implement1.md §3.2 的冲突判定输入就是"新事件 × 现有 state"）。
  给所有类型都必填，是在替一个不存在的需求加约束。
- **它是可选的加字段，所以不产生 schema 版本变更。** 版本号只有一个（ADR-0008），
  它描述的是**资产格式**；加一个向后兼容的可选字段不改格式——
  缺字段的老资产解析成 `null`，和 `last_confirmed` / `supersedes` 一样。
  这不是迁移问题，不需要迁移通道。
- **题面不是证据。** 它是一条**索引**，所以它的可信度要求与 `sources` 完全不同：
  出处必须能解析回原文（否则整条资产不许入库），而题面只是"这句话在讲什么"，
  由抽取器提出、由代码归一化（NFKC + 折叠空白 + 折叠大小写 + 剥掉包裹标点）。
  归一化只能折叠排版，**不能**折叠语义：`数据库` 与 `存储层` 是两个题面，
  把它们并起来是模型提议与人的事（ADR-0026），不是字符串函数的事。

## 后果

- **好**：`assets/state/` 里的每一代状态都能被指着说"它讲的是这件事"，
  于是"新事件推翻了哪一条旧事实"这个问题第一次有了可判定的答案。
- **好**：题面进了受保护路径（`schema/taxonomy.yaml` + `packages/schema`），
  所以它不能被 agent 顺手改——而它改了，两边的状态就会开始互相看不见。
- **好**：模板一致性检查（`C3`）会自动要求四份模板都提到新字段，
  漏一个就红。这正是"两边必须一一对应"（ADR-0010）该有的摩擦。
- **代价**：7 个受保护文件要由人落盘（`schema/taxonomy.yaml`、四份
  `schema/asset-types/*.md`、`packages/schema/src/fields.ts`、`assets.ts`）。
  这是 R2 的既定代价。
- **代价**：v1 期间写下的 `state` 资产会因为缺 `subject` 而报
  `REQUIRED_FIELD_MISSING`。**这是有意的**：它是一条行动指令
  （"补上题面，否则这条状态不参与冲突判定"），而不是"格式坏了"。
  本仓库自己的资产全是 `decision`，所以自举路径不受影响。
- **残余风险**：题面是自由文本，所以**同义而不同形**的题面会漏并、漏报冲突。
  方向是保守的（新建、不报），代价是"同一件事被记成两条"。
  缓解是归并的第三条路：模型只对"题面不同但可能是同一件事"的对子**提议**归并，
  提议进队列（ADR-0026）——人看一眼就能把它们合起来。
- **残余风险**：题面的质量取决于抽取器把它抽成什么样。一个总是给
  `subject: "系统"` 的抽取器会让整个库塌成一个实体，于是每次确认都变成一次冲突。
  这条**不进 CI**（它是抽取质量，归尺子），但 `forge link` 的报告里会打出
  "题面最集中的前几条"，让这种塌陷可见。
