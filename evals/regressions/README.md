# 回归集

**每个真实失败案例在这里留下一条**（R7：每一个错误都变成一条规则或一个回归用例）。

这个目录与 `evals/golden/` 的分工：

| | `golden/` | `regressions/` |
|---|---|---|
| 来源 | 人工确认的判据 | **真实出过的事** |
| 数量 | 固定 20 条起，被阈值引用 | 只增不减，一条一个案 |
| 作用 | 量"现在做得怎么样" | 钉"这件事不许再发生" |
| 谁来写 | 人确认，agent 起草 | 修完那个问题的人 |

**为什么必须是"真实出过的事"**：编出来的失败案例测的是编写者的想象力，
而棘轮的输入是现实。`docs/handbook/gates.md` 里那条"新增一条纪律的顺序"说的是同一件事——
先有真实错误，再有一条规则。

## 现在**进** CI 了（Phase 7 兑现的那句话）

上一版这里写着"在它能自动跑之前，这个目录的绿灯不代表任何东西"。
Phase 7 把它兑现了：`regressions.test.ts` 是这份目录的**执行体**，它做四件事：

1. **每一份 `.md` 都必须登记**（没登记的回归等于一段散文）；
2. **登记表不许有孤儿**（删了案例忘了删登记）；
3. **能自动跑的都自动跑**；
4. **跑不了的必须写清 `why`**——一条永远不跑的检查不许静默地算作"已覆盖"。

今天 7 条里有 5 条是自动执行的（0001 / 0002 / 0005 / 0006 / 0007）。
**0003 与 0004 是明确记账的缺口**：它们的被测对象是 `handoff/apply.mjs`，
一个用完即删的一次性工具——脚本删掉之后就没有东西可测了。
这不是"以后补"，是把"补不了"写下来。

格式不限，但每条必须写清四件事：**当初以为是什么**、**实际是什么**、
**怎么复现**、**留下了什么**。
