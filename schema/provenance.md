# 出处与新鲜度规则（人读的一半）

> 代码侧：`packages/core/src/provenance.ts`（语法与匹配的纯函数）、
> `packages/core/src/asset.ts`（资产判定与违规码）、
> `packages/core/src/extract.ts`（候选断言的判定与违规码）、
> `packages/core/src/model.ts`（模型产出的 sanitize 与它的码）、
> `packages/store/src/spans.ts`（解析，IO 在边缘）。
> 五处与本文档必须一致，漂移由一致性闸门判红（ADR-0010）。

## Span 语法

```
span   := scheme "://" target [ "#" anchor ]
scheme := "file" | "src"
anchor := "h:" 标题 | "t:" 原文片段 | "k:" 键路径 | "L<起>-L<止>"
```

- `file://` —— 工作区/仓库内的文件。CI 里校验的就是这一种。
- `src://` —— `sources/` 层里的来源。**CI 里做不到**（`data/` 被 gitignore），
  所以 CI 遇到它报「无法校验」，而不是静默放过；用户库里的 `forge lint` 能校验它。
- 比较前把空白折叠成单个空格：文档里被引用的句子经常跨行，
  按字节比较会让改一次排版就废掉所有引用——那不是"出处是硬约束"，是"出处是脆弱的字符串比对"。

### 四种锚点

| 锚点 | 指向 | 判据 |
|---|---|---|
| `#h:标题` | 一个 ATX 标题 | 目标文件里有标题归一化后相等 |
| `#t:原文片段` | 一段原文（≥ 8 字符） | 目标文件归一化后**包含**它 |
| `#k:键路径` | 结构化来源里的一条记录（`conv_01/msg_03`） | 由**连接器自己**解析来源后确认键存在（ADR-0014） |
| `#L12-L20` | 行区间（1 基、闭区间） | 目标文件有那么多行 |

`#t:` 的下限 8 字符不是随手定的：太短的片段在任何文档里都能命中，
它会让闸门**通过**，但那不是证据。写 `#t:` 时还要注意别把锚点切在 Markdown 强调符号中间
（`**这段**` 归一化后仍是 `**这段**`，所以 `#t:这段` 不命中）——锚点要指向文档里本来就有的连续文字。
`#k:` 是 v1 里唯一的**结构化**锚点——
`#t:` 在 JSON 上会脆断，因为导出把引号、反斜杠、换行转义成 `\"` `\\` `\n`，
同一句话在原文与原始字节里是两个不同的字符串。

## 两条不能让步的规则

1. **没有出处的断言不许进 `assets/`**（R4）。出处是硬约束，不是元数据奢侈品。
2. **外部证据先落进 `sources/`，再用 `src://` 引用。** URL、工单、线上日志不能直接当 span：
   出处会随外部世界腐烂，而**腐烂的出处比没有出处更糟**——它看起来像证据。

## 违规码（已经进库的资产）

判定的输出是红/绿，每个码对应一种**修法**。合并码等于合并修法。

| 码 | 含义 | 修法 |
|---|---|---|
| `ASSET_FRONTMATTER_INVALID` | front-matter 不合法（缺字段、类型错、值域外） | 补全 front-matter；字段表见 `schema/taxonomy.yaml` |
| `SCHEMA_VERSION_MISMATCH` | `schema_version` 与当前分类法版本不一致（缺版本号 = v0） | 跑迁移通道（`packages/schema/migrate/`），**不要在闸门里顺手兼容** |
| `ID_PREFIX_MISMATCH` | ID 的类型前缀与 `type` 字段不一致 | 改成同一个类型；前缀表见 `schema/ids.md` |
| `PROV_NO_SOURCES` | 没有 `sources`：断言没有出处 | 补上 span |
| `PROV_SPAN_UNRESOLVED` | span 语法不合法，或目标/锚点解析不到 | 去修 span：改掉被引用的原文，或指向仍然存在的那一处 |
| `PROV_SCHEME_UNAVAILABLE` | 本宿主无法校验这个 scheme（例如 CI 里没有 `sources/`） | **这是「无法校验」，不是「通过」**；换 scheme，或到能校验它的宿主里跑 |
| `REQUIRED_FIELD_MISSING` | 类型要求的字段缺失或为空 | 补上；要求写在分类法里，不在文档里 |
| `REQUIRED_SECTION_MISSING` | 类型要求的正文章节缺失 | 按 `schema/asset-types/<类型>.md` 的模板补 |
| `FRESHNESS_EXPIRED` | `state` 超过新鲜度窗口未确认 | 确认是否仍成立；仍成立就更新 `last_confirmed` |

`PROV_NO_SOURCES` 与 `PROV_SPAN_UNRESOLVED` **必须是两个码**：两者的修法不同
（去补证据 vs. 去修 span）。合并成一个码，闸门的输出就从"行动指令"退化成了"报了个错"。
`PROV_SCHEME_UNAVAILABLE` 单独存在的理由更硬：**"本闸门无法校验"和"校验通过"
必须是两种不同的输出**（ADR-0009）。

## 违规码（还没进库的候选断言）

抽取器的产出是**提议**，不是资产。它要被判红，但必须用**另一组码**——
"改一条提议"和"修一条资产"是两种不同的动作，合并码等于合并动作。

这组码分三块，因为**人要不要动手**不同（ADR-0022）。把三块混成一张表，
会得到一份"报了十条、但没有一条需要动手"的报告，而那种报告会训练人无视报告。

### 一、拒绝：越过信任边界的提议（`judgeCandidates`）

| 码 | 含义 | 修法 |
|---|---|---|
| `CAND_NO_TITLE` | 候选没有标题：一条指不出内容的断言无法被审、也无法被引用 | 给它一个能读的标题；没有内容可写说明它本来就不该被抽出来 |
| `CAND_NO_SOURCES` | 候选没有任何 `sources`（或重建之后一条不剩） | 补上 `src://<source_id>#k:<事件 key>` |
| `CAND_SPAN_MALFORMED` | 出处不是合法 span（语法层面） | 按本文档的语法改 |
| `CAND_SPAN_NOT_SOURCE` | 出处用了 `file://` 之类的非 `src://` scheme | 抽取阶段的证据就是事件本身，只能用 `src://` |
| `CAND_SPAN_NOT_IN_INPUT` | 出处指向**本次输入里不存在的事件**——编造的出处 | 只引用输入里存在的事件键；引不出来，说明这条候选本来就没有依据 |
| `CAND_EXTRACTOR_THREW` | 抽取器自己抛了异常（模型端点 500、录像对不上…） | 先修抽取器的异常。**不要把它吞成"这次什么都没抽出来"**——那两件事在报告里长得一模一样 |

判据只有一条，但它是硬的：**候选引用的每一处，都必须是它这一次真的看见过的**
（`sourceId` + 输入事件里的 key）。这一条不判"类型判得对不对"——
准确性归尺子（`evals/`），可追溯性归代码。两者混在一起，会得到一个
"永远正确的抽取器"而不是一个更准的。这是"模型负责抽取，代码负责不信任"
落在代码里的那一处（implement1.md §3.1，反模式 2）。

### 二、丢弃：整条提议作废（`sanitizeCandidates`）

模型的产出在进库前会被逐条硬化：类型必须在受控词表里、必须有标题、
必须至少留得下一条**指得回本次输入**的出处。做不到的整条丢掉，代码记一笔。

| 码 | 含义 | 修法 |
|---|---|---|
| `CAND_TYPE_UNKNOWN` | 模型给的类型不在受控词表里（不是 `decision` / `state` / `event` / `rule` 之一） | 受控词表是**四选一**，不是自由文本。整条丢掉——"顺手归到最近的类型"会让分类法在模型手里慢慢变形 |
| `CAND_RESPONSE_UNPARSEABLE` | 模型的响应读不成约定的形状：JSON 坏了、根不是对象、没有 `assertions` 数组 | 去调 **harness**（提示词 / 输出契约 / 分块），不是换模型（implement2.md S17） |

### 三、降级：代码已经处理完，只留下痕迹

这里的码**不需要任何人动手**。它们存在的理由是反面：
静默裁剪比不裁剪更糟——它会让"模型很准"这个印象没有任何反例。

| 码 | 含义 | 修法 |
|---|---|---|
| `CAND_CONFIDENCE_FORCED` | 置信度被压到入库上界 `LOW_CONFIDENCE`（模型自称 0.99 也只按 0.3 算） | **不需要动手**。这是"低置信度起步"的执行体（implement1.md §3.1），也是模型产出进不了 `assets/` 的那道门 |

### 出处是**重建**的，不是照抄的

`sanitizeCandidates` 不会把模型写的出处字符串原样存下来：它逐条解析，
只留指得回本次输入的那些，再用 `formatSpan` **重新拼**一遍。
理由：最终存进资产、并且 `SpanIndex` 拿来查表的就是这个字符串
（`buildSpanIndex` 用的就是 `formatSpan` 的输出）。差一个空格，
资产里的 `sources` 与索引里的键就是两个字符串——**查不到，而且是静默查不到**。
重建顺带做掉去重与排序（同一处证据说两遍不算两处；顺序要确定，R6）。

大小写变体（`SRC_xxx`）**不在**重建之列：目标的比较是逐字节的，
它会被当成编造的出处**丢掉**。这是有意的——"大小写不同但看着像"
正是需要人看一眼的那类东西，静默归一化会让它消失。

## 新鲜度只挂在 state 上，而且**不进闸门**

- `state` 会过期，所以要 `last_confirmed` + 窗口（默认 30 天）。
- `decision` 一旦 accepted 不可变；`event` 是发生过的事；`rule` 靠 `origin_incident`
  溯源而不靠时间。给它们定过期时间只会制造一个没有内容的检查项，而没内容的检查项会被跳过。
- **新鲜度检查故意不在提交闸门里**：闸门的判据必须只依赖输入，而新鲜度依赖"今天"。
  把时钟塞进闸门，会让一份没动过的资产在某天早上突然变红，而红的原因是"时间过去了"——
  那是维护任务（Phase 7 / S26）的职责。它由 `forge lint --today` 单独跑。
