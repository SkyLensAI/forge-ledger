没有 key 时，S17 的基准报告只能是"协议 + 可测证据"，不能是一组分数

问题

S17 的交付物写的是"一份基准报告"，退出条件是"精确率/召回率达标，且连续 3 天稳定"。

而本仓库没有 API key。于是有两种做法：

  • 造一份合成 cassette（手写模型的回答），让它跑出好看的分数，写进报告。
  • 如实写：模型路径没有在真实模型上量过，交付的是"要量什么、怎么量"的协议 ＋ 已经能测的那部分证据。

第一种做法在这个仓库里有专门的名字：让模型给自己发合格证。 手写的回答可以逐条贴合 20 条 golden 用例——那测出来的是"出题人也会答题"， 不是抽取质量。而这份分数一旦写进 README，它就会变成后续所有讨论的前提， 且没有人能从那个数字里看出它来自一份手写的录像。

考虑过的选项

  1. 合成 cassette + 分数。 报告好看，但那个数字是编的（见上）。
  2. 不写报告，等有 key 再说。那就是"没有 eval 就说效果不错"的反面： 连"该量什么"都没留下，下一个人（或下一个 agent）得从零想一遍。
  3. 只写协议：把阈值、量法、复现命令、验收判据写清楚，分数留空。
  4. 协议 + 把"现在就能测的部分"全部测掉：信任边界（E7）、 管道的确定性（同一份录像跑两次字节相同）、sanitize 的逐条行为、 以及词法基线在同一把尺子上的分数（0.882，它不需要 key）。

选定

选 4。 具体落在三处：

  • evals/README.md 新增「Phase 4 · 模型路径怎么量」一节：量什么、用什么命令、 阈值从哪来、什么算达标、以及当前状态是"未量过"。
  • evals/runner/main.ts --extractor model-replay 是那条命令：它对着一份录像跑， 走的是与真实调用完全相同的代码（录制完立刻回放，只走一条路）。
  • 仓库里不放任何 cassette（ADR-0021）。所以那个抽取器在没有 FORGE_CASSETTE 时抛错，而不是返回空——"没有录像"与"模型什么都没抽出来"必须能被分开。

报告里一个字都没提到"模型抽得准不准"的结论，因为那需要一个真实运行。

后果

  • 好：交付物是可执行的，不是一段承诺。有人拿到 key 之后， 两条命令就能得到第一份真实报告，而"怎么算达标"已经写在前面了 （阈值 + E2/E6 的人工确认，与 Phase 3 同一套）。
  • 好：把"未量过"写进 README 的当前进度表，而不是留在 PR 描述里。 一份把状态写成"完成"的文档，比一份写得难看的文档更危险。
  • 好：Phase 3 那句"阈值是地板，不是目标"因此有了下半句—— 地板现在也铺到了模型路径上，只是还没人在上面走过。
  • 代价：Phase 4 的退出条件在本仓库没有达成，而这会一直显示在 README 上。 这是对的：它是事实，而"用一份合成录像把它变成绿色"是把闸门当成装饰。
  • 残余风险：没有真实运行，就没有真实失败案例，evals/regressions/ 里 关于模型的条目只能是"我在开发中踩的"（例如 0002 那条编排错位）， 而不是"模型在真实数据上踩的"。棘轮的输入因此少了一类—— 而这正是 Phase 4 之后必须尽快补上的东西：第一件真实失败案例。
