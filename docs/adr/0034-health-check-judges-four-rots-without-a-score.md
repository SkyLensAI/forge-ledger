# 健康检查判四类腐烂，但不给库打健康分

## 问题

implement2.md 给 P7 写的第一件事是"Linter：孤儿页、索引漂移、过期断言、静默被取代"，
交付物写的是"健康检查"。四类腐烂里，**只有一类是已有的**：
`FRESHNESS_EXPIRED` 在 Phase 1 就写好了，而它刻意**没进闸门**——
理由是闸门的判据必须只依赖输入，而新鲜度依赖"今天是几号"。

剩下三类那时连判据都没有：

| 腐烂 | 为什么它到现在都没被看见 |
|---|---|
| 孤儿页 | 没有任何地方问过"这条资产还有没有邻居" |
| 索引漂移 | `index/` 是可重建的，所以漂移只在"删掉重建"时才暴露，而没人会定期删它 |
| 静默被取代 | `detectConflicts` 只在**有新候选**时看那个题面（S19）；没有新候选时，两条 `active` 会一直并存 |

于是有两个问题要现在定下来：

1. 这四类判据住在哪儿、怎么判；
2. **报告长什么样**——尤其：要不要给库一个"健康分"。

## 考虑过的选项

1. **把健康检查做成 `forge lint` 的一部分**（多几个 flag）。
   否决：`lint` 的判据是"这份资产合不合规"，它的宿主是**闸门**；
   而健康检查的判据是"这个库还找得到自己吗"，它的宿主是**维护任务**。
   两者的时钟依赖完全不同（一个不许有时钟，一个必须有），塞进一个命令之后，
   早晚会有人把新鲜度也接到闸门上——那是一份没动过的资产某天早上自己变红的原因。

2. **给库打一个 0–100 的健康分**，像体检报告那样。
   否决。不是因为它难算，是因为**它会改变行为的方向**：
   有了分数，"哪件事该被处理"就变成"怎么把分数弄回去"，
   而最省事的提分方式是删掉报错的那几条。这个产品最不能做的就是
   把"库还诚实吗"变成一个可以被优化掉的指标。

3. **拿"离 500–1000 条的漂移阈值还有多远"当进度条。**
   采纳，但**只当刻度**：它进报告，但不挂任何判定。
   判据很直接——"条数到了"不是问题，"到了之后还看得见问题"才是。

4. **默认把四类都判，宿主没给事实就说"没查"。**
   采纳。索引层与审计的事实由宿主读出来（core 不认识 SQLite、不认识文件），
   而"宿主没给事实"与"查过了没问题"必须长得不一样（ADR-0009 的那条理由）。
   报告里因此有一节写着**本次没查什么**。

## 选定

- 判定与渲染都进 `packages/core/src/health.ts` 与 `report.ts`（纯函数、零 IO，
  时钟由 `today` 注入），三个宿主（CLI / 定时任务 / 周报）走同一个入口。
- 四类各一个码，**孤儿是 `info`**：它不进退出码。一个长期挂着几十条不需要动作的报告，
  会让人学会无视它——而"红的时候有人信"是这份报告唯一的价值。
- `severity` 三档（`error` / `warn` / `info`），但**只有 `info` 不进退出码**：
  `error` 与 `warn` 的区别只影响排序，不影响"要不要动手"。
- **不打分**。报告里只有清单、计数和"先做这三件"。
- 报告里带一行规模刻度（`DRIFT_SCALE`，来自 [14] 的 500–1000），
  **不挂任何判定**。

两条**范围**规矩是实测撞出来的，写在这里因为它们是判据的一部分：

- **孤儿只查 `decision` / `state` / `rule`。** `event` 是时间线，它按定义就是
  一条条独立的事件；把事件算进来，孤儿清单会被时间线淹没——而**被淹没的清单等于没有清单**。
- **孤儿不看已经退休的资产**（`superseded` / `retired`）：一条被取代的状态
  **本来就该**没人引用它。第一版没排除它们，于是"标了 superseded 却没有接班人"
  那一条会被报两遍（一遍是它真正的问题，一遍是"没人引用它"）。

## 后果

- **好**：`HEALTH_DUPLICATE_ACTIVE` 补上了一个真实的盲区——冲突判定看不见
  "库里已经存在两条 `active`"（它只在新候选到来时看题面）。而"两条都说是现在的样子"
  正是这个产品最不能出的静默故障。
- **好**：报告是逐字节确定的（基准日是输入，排序键写死），所以它可以被快照、
  被 diff、被放进邮件而不会每次都"变了"。探针每次 CI 都验证这一条。
- **代价**：健康检查**只读**——它不修任何东西。这是有意的：
  一个会自己动手的健康检查（"发现过期就刷新 `last_confirmed`"）
  会让库永远看起来新鲜，而那正是新鲜度任务存在的理由（ADR-0036）。
- **代价**：报告会变长。缓解是截断 + "共 N 处"那句（静默截断会让"一共 20 条"
  与"只显示 20 条"读成同一句话）。
- **残余风险**：孤儿判定里的"证据邻接"按**来源目标**（`scheme://target`）算，
  忽略锚点。同一份材料的两条断言因此互为邻居——这是对的，但它也意味着
  "一份被大量引用的来源会让它下面所有资产都不算孤儿"。
  在只有一两个来源的早期库里，孤儿会偏少。记在这里，不假装它准。
