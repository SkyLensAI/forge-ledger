# 模型产出永不直接进 `assets/`：一条不可配置的判据，加一条候选区

## 问题

S15/S16 的要求可以压成三句话：**低置信度起步**、**用真实抓取到的来源重建 `sources`**、
**丢弃编造的内容**。难点不在"要不要做"，在于**做在哪一层**。

一步步退让的写法是这样的：先写进提示词（"只引用上面列出的 key"），
再加一条"如果置信度低就进候选区"，然后把阈值做成参数，最后有人为了跑通一次演示
把它调成 0——每一步都合理，合起来就是 implement1.md 反模式 6
（让运行时的 agent 自动覆盖用户已有的状态，信任一次崩掉就回不来）。

还有一个具体缺口：Phase 3 的 `judgeCandidates` 判的是"这条提议有没有越界"，
它**不改变**提议；而 S15 要求的是**改变**它（重建出处、压置信度、丢弃）。

## 考虑过的选项

1. **把要求写进提示词 + 在 runner 里加几条 if。** 最省事。代价是：
   边界变成了散落在调用点的一串条件，而每一个调用点都要记得写全。
   换一个调用方（MCP server）就少一遍。
2. **只加一个"如果 `origin === 'model'` 就进候选区"的分支**，置信度照收模型报的值。
   这一条挡住了"直接进库"，但把"低置信度起步"整个丢掉了——
   而低置信度正是候选区里排序、以及将来人工确认顺序的依据。
3. **三件都在严格函数里做，而且分成两段**：
   `sanitizeCandidates`（把模型的话**铸成**候选：重建出处、压置信度、丢弃编造内容）
   → `guardCandidates`（决定去哪：`admit` / `inbox` / `reject`）。
4. **不要候选区，全部进 `assets/` 但打上 `status: proposed`。**
   那就回到了"让 LLM 直接写正式资产"——implement2.md 明确把它列为不可逆点之一
   （垃圾污染库并变成先验）。

## 选定

**选 3**，并且把它写成两条**互相独立**的判据：

- **`sanitizeCandidates` 是"铸币"**：模型给的是 `unknown`，**只有它**能把那些东西
  变成 `CandidateAssertion`。这一条在**类型层面**成立——`parseExtractionResponse`
  返回 `unknown[]` 而不是 `CandidateAssertion[]`，于是任何想直接用模型输出的代码
  都编译不过。出处逐条解析、只留指得回本次输入的那些，再用 `formatSpan` **重建**字符串
  （存下来的那个字符串就是 `SpanIndex` 查表用的键，差一个空格就是静默查不到）；
  置信度 `min(模型说的, 0.3)`；类型不在受控词表、没有标题、一条出处都留不下的整条丢掉。
- **`guardCandidates` 是"发证"**：它**先自己复核一遍出处**（`judgeCandidates`），
  不假设上游 sanitize 过——这是换一个调用方时的兜底。然后三选一，
  其中 `origin === "model"` → **永远 `inbox`**，与置信度无关、与策略无关、**不可配置**。
  把它做成配置项等于给"让模型直接写正式资产"留一个旋钮，而那个旋钮迟早会被拧。

**候选区的形状**同样是判定的一部分（三条，都写进结构而不是写进规矩）：

1. **`_inbox/` 是 `assets/` 的兄弟目录，不是它的子目录。** ADR-0012 定的是
   "约定即集合：任何带 front-matter 的 markdown 都是资产"，而 `assets.scan()`
   递归扫整个 `assets/`。候选区若住在里面，它的每个文件都会立刻被当成资产——
   于是要么它必须长成一份合法资产（那就不是候选了），要么闸门会为一批
   "还没准备好"的东西长期报红（那会训练人无视闸门）。
2. **候选是 JSON，不是 markdown。** 这条更硬：markdown + front-matter 就是资产的写法，
   而候选**不是资产**。用 JSON 之后，"候选区里的东西不可能是资产"这件事
   **在结构上**成立，不依赖任何人记得这条规矩（R8）。
3. **候选 ID 是内容寻址的**（前缀 `cand_`，取值是 sha256(类型 + 出处列表)），
   **记录里没有时间戳**，而且这个前缀**刻意不进 `schema/ids.md` 的前缀表**——
   那张表是**资产** ID 的表，而候选不是资产。把它混进去会让"哪些 ID 属于资产"
   这个问题第一次变得需要解释。
   于是同一份来源用同一个 harness 抽两次，得到的是同一个文件、同一份字节——
   重跑不产生第二份候选（R6）。"什么时候抽的"是审计层的事（Phase 7 / S27）。

`admit` 这一档保留着，尽管 v0 的抽取路径永远走不到它：它是"非模型来源按置信度入库"
那条路的位置，而没有它，那条路将来只能从后门加。CLI 反过来把
"抽取路径上出现了 `admit`"当成**不变量违例**报错——那说明守卫被改松了。

## 后果

- **好**：三条要求各自有了一个能指认的执行体，而且都能单独测
  （`packages/core/test/model.test.ts` / `guard.test.ts`）。
- **好**：`origin: "model"` 这一条判据与 `LOW_CONFIDENCE`（0.3）**两条门同时存在**，
  由测试钉住"入库线必须高于 0.3"——少任何一条，另一条都还能独立挡住模型产出。
- **好**：候选区不可疑地进不了资产集合，所以 `pnpm gate:ci` 的资产闸门
  不需要为 Phase 4 加任何豁免。**没有豁免**比"有一个写清楚的豁免"结实得多。
- **代价**：多了一层 `sanitize → guard` 的间接，以及一个"候选不是资产"的新概念。
  代价换来的是：候选区可以被人随手编辑、删掉、重跑，而不会碰到正式资产一寸。
- **代价**：`_inbox/` 是第四层目录。`ensureVault` 现在建五个目录。
  已知的别扭点：它不是"三层权限规则"之一（ADR-0015），而是**第四种东西**——
  一种"尚未成为资产、也永远不会自动成为资产"的暂存。这条不一致是有意的。
- **残余风险**：`admit` 在 v0 是**死代码**（抽取路径走不到）。
  留着的理由是"它表示一条将来会有的路"，但这也意味着它在 Phase 5 之前
  不会被真实用法检验过。缓解是 CLI 把它当成不变量违例——至少它不会静静地错。
- **残余风险**：候选的去重靠内容寻址 ID，所以"同一处证据被两条不同的措辞抽到"
  会是**两条**候选。人去确认时会看到两条说的是一件事。缓解是 `promote` 时按
  `(类型, 出处)` 拒绝重复，但那是在**确认**那一步才拦，不是抽取那一步。
